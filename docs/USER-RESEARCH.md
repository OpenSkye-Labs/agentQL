# What users want from desktop SQL clients — research for the AgentQL roadmap

**Method / caveats.** Sources read: ~12 Hacker News threads (Ask HN, Show HN, DBeaver/TablePlus/Beekeeper/DataGrip/Vanna/text-to-SQL), ~12 GitHub issues (TablePlus, Beekeeper, DBeaver, DbGate, TablePro), one dev.to poll thread (~80 comments), Supabase MCP docs, two agent-incident write-ups, and review aggregators as secondary colour. **Reddit could not be read**: fetches to reddit.com are blocked in this environment and the search backend never returned reddit URLs, so Reddit sentiment is absent, not summarised second-hand. "Many" below means ≥4 independent voices across ≥2 sources; "one loud person" is flagged as such.

## (a) Top 15 requested features, ranked by recurrence

1. **Fast, native, low-memory — "launches instantly, shows me the tables".** The single most repeated theme. jmnicolas: "Dbeaver is certainly not fast… In fact VSCode starts faster"; wink reports "480 MB of RES RAM" for one small Postgres DB; mekster: "DataGrip is heavy. It takes seconds to launch… the interface is cluttered"; pkphilip on Electron: "it slows down everything"; mococa: "I would use it if it weren't based on Electron." TablePlus is loved for exactly this ("lightning fast", drej; "native, fast and beautiful", Gianluca Andreotti). Sources: HN 25123849, 39660592, 18935138, 37732329, 42320032, 19160808, dev.to poll.
2. **Linux parity.** TablePlus's "Linux version" issue (#1056) has 54 👍; Capterra reviewer: Linux "still in alpha stage and has been for years" (paraphrase, secondary); rathboma built Beekeeper because TablePlus "didn't even have a Linux version"; silisili: "dbeaver was the only tool that worked without a huge headache in Linux"; lf-non: DBeaver dark mode on GNOME has "barely visible text." Sources: TablePlus #1056, #3683, HN 37732329, 18935138, 39660592.
3. **Many engines in one tool.** DBeaver's main praise (vietthan: "many databases of different engines"; hooverd: "It just works, and for lots of DBs"). Top TablePlus asks are all drivers: DynamoDB #666 (66 👍), ClickHouse #670 (66), BigQuery #2083 (43), DuckDB #2262, Athena, InfluxDB. Vector DB support asked of DataGrip (vunderba). Sources: TablePlus issues, HN 36625835, 42320032.
4. **Schema-aware autocomplete that works out of the box.** 9dev on JetBrains: "in-editor completion of queries against your schema… wouldn't switch to any external tool anymore"; kevinob11 on Postico: "lightning fast and always stays responsive"; mypastself on DBeaver: autocomplete "needs configuring"; briHass praises SSMS IntelliSense. Comparison blogs agree DBeaver CE suggests columns from the wrong tables (secondary). Sources: HN 46547226, 28706250, 36625835.
5. **Safety rails: run-current-not-run-all, transactions, read-only connections.** Beekeeper #1679 (accepted, shipping in 6.7): "We've had occurrences of data loss because somebody accidentally ran ALL queries in the current editor"; maintainer: "Run current is the safer default… it's less dangerous." Outerbase HN: Dachande663 noticed it "doesn't actually use transactions", bottled_poe wants "an option to enforce the use of transactions." shortrounddev2 likes that DBeaver grid edits are a transaction committed with Ctrl+S. NoSQLBooster praised for read-only connections. Sources: Beekeeper #1679, HN 42320032, 39660592, dev.to.
6. **ER diagrams / schema visualisation.** Beekeeper #1160 (requested 2022, closed as completed Apr 2026); ggregoire asked TablePlus for it in 2019 ("DBeaver offers them"); Derek Crosson: "I love DBeaver and that it can generate entity relationship diagrams"; pier25 wants "some sort of schema designer" in Postico; e12e: pgcli "doesn't help with visualizing schemas." Sources: Beekeeper #1160, HN 19160808, 30798672, 23208181, dev.to.
7. **Big / wide result sets without freezing.** Beekeeper #752: "a table with only 155k records, and 49 cols is excruciatingly slow"; "123 columns and only 3k rows and it's basically unusable"; davidalexisnyt: "Reading the entire resultset into memory before rendering makes the UI unusable." DBeaver has a long tail of Java-heap OOM issues (#2096, #5851, #34854, #22056 export of 102 GB table "closed as not planned"). TablePlus-Linux #127: sorting a large set hangs the UI. InfiniteRand: "I have not really seen any GUI approach that scales smoothly from small amounts of data." Sources listed inline.
8. **Pricing: one-time, per-developer, no nag.** kamranjon to Beekeeper: "If you sold a one-time license… I'd gladly pay $100"; taffit: "Biggest issues for me: Subscription based payments"; hackerm0nkey on TablePlus: "Why do you expect me to renew my license to get your updates?"; news_to_me: "Bummer it has a per-seat license, instead of per-developer"; dahdum left Aqua Data Studio when it went "$500/yr"; RachelF on DBeaver PRO "$500 a year"; cowmix wants to "throw them $50 a year for the CE version"; usaphp: "I would rather support a solo developer than a faceless corporation." Sources: HN 37732329, 22909408, 19160808, 23208181, 39660592, 46547226.
9. **Keyboard-first / vim keys / remappable shortcuts.** TablePlus #1237 "Vim/Emacs/Nano keybinding" 65 👍; DBeaver "vi mode" #37897; taffit's "biggest issue" with Beekeeper is "missing option to adjust the keyboard shortcuts"; Sqlit thread users want "/" to filter and "just use shortcuts to do things" (tanin); exabrial calls tree UIs "the bane of usability." Sources: TablePlus #1237, HN 37732329, 46276002, 19160808.
10. **Import / export / dump / copy-rows that just work.** Kevin Peters on Beekeeper: no copy-rows-as-CSV/JSON — "That is the deal breaker there"; dpcx on DataGrip: full dumps need external MySQL tooling; bendotero keeps Sequel Pro "for import/export"; bkev: TablePlus export "single-quotes all data types"; TablePlus #331 import SQL dumps. Sources: dev.to, HN 28706250, 19160808, TablePlus issues.
11. **Modern connectivity: SSH, IAM/SSO, Kubernetes port-forward, SQLite over SSH.** enz: DBeaver "built-in support of SSH tunnels is a big plus"; TablePlus #2952 "editing SQLite over ssh" 38 👍, #2007 IAM auth to RDS; DBeaver #3270 ("not found a single GUI app which can support IAM tokens"), #10862 SSO, #15242 Kubernetes proxy — shipped **Enterprise-only** (👎5 on that reply); ndom91 submitted RDS IAM to Beekeeper. Sources listed inline.
12. **Navigation ergonomics: FK click-through, tables first, no 7-click trees.** bzzzt likes DBeaver's "clicking through on a foreign key"; kriskoch's top Linux ask for TablePlus is exactly FK jump (#3683); wink: "why it doesn't show the tables first, I have to go through Schemas -> Public"; thiht on pgAdmin: "7 clicks to access a table in the tree." Sources: HN 23208181, 18935138, 36625835, TablePlus #3683.
13. **Charts/dashboards from a query.** yesthisiswes: "My favorite part [of TablePlus] was that you could hook a query up to a chart" (live dashboard); JimmyL wants "a view where I could render that into a line or bar chart" that updates with the query; atombender praises DataGrip's graphing; others reach for Metabase. Sources: HN 42320032, 18935138.
14. **Schema diff / data diff / migration generation.** paulryanrogers: DBeaver schema compare "not in the community version"; brightball misses Navicat's "data sync and schema sync tools"; 0XAFFE likes pgModeler's "diff function to generate migrations"; spricket: DBeaver "SQL generation from structure or data edits… cranking out DB migrations"; atonse wants Postgres in Redgate SQL Data Compare. Sources: HN 39660592, 18935138, 28706250, 30798672.
15. **Saved-query history, versioning and sharing.** TablePro #2505 "Saved queries have no history… An edit overwrites what was there" (shipped Sep 2026); Querya #1064 git-linked query library + team connection profiles; Alifatisk asks Outerbase "Is there a plan to support collaboration?"; Beekeeper #256 open/save .sql files; mooncakes_ooohh left Beekeeper because "it didn't save my connection by default." Fewer voices than 1–14 but consistent. Sources listed inline.

Honourable mentions (real but thinner): persisting plugins across updates (DBeaver #5317, open since 2019, ~100 👍 across comments: "After almost 6 years… I doubt it will ever be completed"); theme follows OS (DBeaver #21600); full-text search across a whole DB (TablePlus #425, 49 👍); JSON/JSONB editing (nickreese); PostGIS rendering (mvexel); visual query-plan — surprisingly rare in user threads (betterDb #49 only; it's a vendor feature in DbVisualizer/DataGrip, not a loud ask).

## (b) TablePlus: likes / dislikes / switching triggers

**Likes (many):** speed and native feel ("lightning fast, the UI is so easy to use" – drej; "snappy and mostly fine" – mekster; "Well designed and fast" – danroc); multi-DB in one app ("the fact that it also works with multiple databases is huge" – kevinob11); query→chart; responsive solo developer; dark mode; "80–90%" of Postico with more engines. Several Sequel Pro/Postico refugees landed here (rusty_pete, boundlessdreamz, joshuat).

**Dislikes:** (1) **Linux build** — long "alpha" label, missing FK jump/quick filters until 2026, hangs on large sorts, 404 .deb on AUR (many, mostly older). (2) **Licensing** — per-device/per-seat, update-renewal model, free tier "2 tabs" (zaszrespawned: "they need to allow more than 2 tabs"), one EULA clause that made a lawyer refuse it (drej/steve19 — one loud thread, 2019). (3) **Windows/Linux lag macOS** — Oracle missing, blurry text (altmind), AI assistant "Not in Windows or Linux" (Braunson, 2025). (4) **AI feature half-baked** — fabswt: "In all honesty, the feature feels unusable at this point"; angel-forge: "Where did the AI option go?" (5) Occasional "Very buggy and unintuitive" (mthoms — minority view).

**Switching triggers:** need Linux; need an engine TablePlus lacks (DynamoDB/ClickHouse/BigQuery); hit free-tier tab limit and object to the licence; team purchasing friction (EULA/per-device). Loyalty anchor: nothing else is as fast and clean on macOS.

## (d) AI integration: wants, fears, trust requirements

**Wants (many):** _Schema-aware_ — johtso: "currently do a lot of switching back and forth with ChatGPT… having your database schema automatically be part of the prompt would be great"; fabswt would pay for TablePlus to "send the whole database schema (or relevant parts of it)". _BYO key / existing subscription_ — iloveitaly wants "users' own OpenAI keys"; woodymendoza: "I'd love to use my Claude credentials"; Outerbase's burcs considered BYOK to avoid paying for an OSS project's inference. _Copilot-style inline completion_ (MatanYadaev; sagaro: "github copilot style sql IDE"). _Local models_ — DBeaver #36951 (Ollama in CE) "especially for users who need to work with sensitive data locally"; sagaro: local "to get the nod from the IT/Sec department." _Correct-and-iterate chat_ — eurekin: "a chat interface, where you correct the result and provide more contextual information about those columns." _Explain/optimise_ and charts appear in vendor lists more than user threads.

**Fears (many):** _Hallucinated schema_ — Vanna HN: "GPT-4 sometimes deviates from examples or schema" (qiller); weekend-MVP author: it "confidently generated SQL for tables that didn't exist." _Business meaning_ — panarky: it "can't understand the meaning of the data just by looking at column names"; swimwiththebeat: "enums and data types specific to our business… will never be in these foundation models"; fivetenpen: "there is no one to validate that query"; teaearlgraycold: "the users that get the most value… are the ones without the ability to validate the generated SQL." _Destructive writes_ — kleiba: "could it… delete parts of your data?"; the Apr-2026 Cursor/PocketOS wipe ("deleted the database in just nine seconds") and tim-schipper: "A rule in a prompt is a suggestion… If you want a hard constraint, you need system-level boundaries." _Data leaving the machine_ (DBeaver #36951; antman: "SQL AI is currently an academic exercise" for messy orgs). _Cost_ (gbot asks if a free key works; DataGrip AI credits). _Half-shipped features_ (TablePlus AI: "unusable", vanished, Mac-only).

**What would make them trust it:** enforcement in the DB session, not the prompt (pgen: `SET default_transaction_read_only = on`; Supabase MCP: run as a read-only Postgres user, "elicitation… may not catch every destructive operation and is not a security guarantee"); approval that distinguishes human SQL from model SQL ("Approving your own statement doesn't approve SQL the model wrote"); explicit consent before metadata is sent plus a visible log of the full request (DBeaver wiki); scoping which tables the model sees; an agent loop that inspects schema, runs probe queries and checks totals (brotchie) and _asks clarifying questions_ (tqi: "the most value… comes from the agent asking clarifying questions and pushing back"); a place to attach column meaning/metrics so answers stop drifting (programmertote's YAML metadata; thom's "structured intermediate layer"); AI-run queries landing in the same query history as yours (DataGrip 2026.2).

## (e) Unsolved pain points / opportunities

1. **Native speed + Linux parity + many engines + fair licence** has never shipped in one product: TablePlus has 1–2, DBeaver has 2–3, DataGrip has 2–3. The gap is explicit in rathboma's origin story and in every "if only TablePlus ran on Linux" comment.
2. **Modern connectivity is paywalled** — K8s port-forward, IAM/SSO, SQLite-over-SSH are PRO/EE in DBeaver and absent/weak elsewhere.
3. **Big-result ergonomics** — streaming/virtualised grids for wide tables and multi-GB exports still crash the incumbents.
4. **Safety as a product feature** — run-current default, forced transactions, read-only connections, production tagging: asked for everywhere, implemented piecemeal.
5. **AI with enforcement, not vibes** — no mainstream client combines schema-scoped prompts, BYOK/local models, DB-session read-only, per-statement approval and an audit trail. pgen is the only one framing it this way and it's Postgres-only.
6. **Business-meaning layer** — nowhere for a user to say "revenue means X, status 3 means cancelled" so the model stops guessing. Every text-to-SQL thread ends here.
7. **Query versioning/sharing** — history, git-aware saved queries, team connection profiles: just now appearing (TablePro, Sep 2026).

## (f) Recommended priorities for AgentQL

1. **Keep "fast + native + Linux-first" as the headline** (a1, a2, e1). Tauri already gives this; publish startup time/RSS vs DBeaver/DataGrip and treat Linux as tier-1 (packaging: .deb/AppImage/Flatpak — Beekeeper #22 Flatpak is a top ask). _Partly covered._
2. **Make safety the default**: run-current on Cmd/Ctrl+Enter, auto-wrap grid edits and ad-hoc DML in a transaction with explicit commit, per-connection read-only + "production" tag with confirmation on writes (a5, Beekeeper #1679, pgen). _Partly covered_ (AI writes gated; human path not yet).
3. **Enforce AI read-only at the DB session**, not just via `agent_allow_writes`: `SET default_transaction_read_only` / read-only user for agent sessions; approval scope distinct for model-authored SQL; auto-`LIMIT` on bare selects (d). _Partly covered_ — approval exists; session-level enforcement is the trust unlock.
4. **Audit log + consent for what the model sees**: first-use prompt per connection before schema is sent, table-scope picker, viewable raw request, AI-run queries in the normal query history (DBeaver wiki, DataGrip 2026.2). _Not covered._
5. **Local-model option (Ollama/OpenAI-compatible base URL)** alongside BYOK and Claude Code/Codex CLI — the single loudest AI ask in DBeaver's tracker and the IT/Sec unlock (d). _Not covered_ (providers: anthropic/openai/CLIs).
6. **Schema-aware inline completion** (a4) — the thing DataGrip users "wouldn't switch" without. CodeMirror + live catalogue; later let the agent provide ghost-text. _Partly covered_ (editor exists; quality unknown).
7. **Semantic notes / data dictionary** the agent reads: per-table/column descriptions and named metrics stored with the connection, injected into prompts; AI can draft them (d, e6). _Not covered_ — differentiator.
8. **ER diagram + FK click-through + schema diff** (a6, a12, a14): ERD from catalogue (mermaid/dagre), FK jump in the grid, and DDL diff between two connections — all CE-paywalled or missing elsewhere. _Not covered._
9. **Virtualised grid for wide/huge results + streaming export** (a7, e3). _Partly covered_ (react-virtual present; verify wide tables and 100k+ rows, add streaming CSV/SQL export and import of dumps, a10).
10. **Connectivity beyond SSH**: Kubernetes port-forward and AWS RDS IAM/SSO tokens (a11, e2) — free where DBeaver charges. _Not covered_ (SSH only). Charts/dashboards (a13) are already an AgentQL strength; keep the one-click "query → chart" path dead simple since that's TablePlus's most-missed feature.

Pricing signal for later: users repeatedly say they'd pay ~$100 once or ~$50/yr donation, resent per-device seats and update-renewal gates, and a lawyer-safe licence matters for team adoption (b).
